The .eco Protocol

Write an experiment as plain text — declare your hypotheses before you run — and the engine runs it, grades it, and exports it. This is the reference for every keyword and the round-trip that ties the browser, the runner, and the report together.

An .eco file is the connective tissue of the whole ecology kit. You can write one by hand, or type into the Interactive Lab's Workbench and let its transfer box emit the lines for you. Either way, the same seeded, oracle-tested instruments grade it — so a protocol is a reproducible experiment you can store, re-run, and hand in.

The round-trip

1 · browserWorkbenchType field counts, a census, a cross. It computes live.
→
2 · transfer.eco fileThe transfer box rewrites what you typed as protocol lines. Save it.
→
3 · runnerGradeecologyExperiment runs it and marks every hypothesis.
→
4 · exportReportCSVs (Excel/R), a print-ready report.html, and a session file.

↺ Drop the exported ecology-experiment-session.json back onto the Interactive Lab to see the whole run drawn as charts — the loop closes.

Keywords

Every line is keyword: arguments. Blank lines are ignored, and # starts a comment (to end of line). A malformed line is reported and skipped — never guessed at — and the run continues with what parsed.

setup

Header — the world

LineMeaning
name: <text>The study's title, shown atop the report.
keys: <N>How many distinct keys (species) the simulated world holds.
seed: <N>The random seed. Same seed ⇒ byte-identical numbers, so a run reproduces.
window: <N>The sampling window, in operations, for turnover and rate readings.
name: meadow disturbance study
keys: 100   seed: 42   window: 250
simulated traffic

phase — a chapter of the workload

Each phase runs a stretch of operations with a named traffic shape. Phases are what the diversity, turnover, and dispersion instruments read.

FormMeaning
phase: <label> uniform <N>N ops of even traffic — every key equally likely.
phase: <label> hot <N> <hotset> <pct>N ops where <hotset> keys carry <pct>% of the traffic (a dominated community).
phase: <label> churn <N> <pct>N ops with <pct>% births and deaths — turnover the life table reads.
phase: graze   uniform 2000        # even grazing
phase: bloom   hot 2000 5 90        # 5 keys take 90% of the traffic
phase: seasons churn 1500 55        # seasonal turnover
abiotic environment

factor — the conditions

Factors set the abiotic environment. They scale the theory models below — a smaller area lowers carrying capacity; wind aids colonization; distance raises isolation.

LineEffect
factor: area <x>Habitat area — scales carrying capacity K and island area.
factor: wind <x>Dispersal aid — scales the island colonization rate c.
factor: distance <x>Isolation from the mainland — raises effective rates.
factor: temperature <x>Ambient temperature — an additional abiotic knob.
factor: area 0.5        # a small pond…
factor: wind 1.3        # …with helpful wind…
factor: distance 0.8    # …somewhat far from the mainland
theory bench

model — run a classic model

Each model: line runs a named population/genetics model on the theory bench, feeling the factors above. Argument order is shown here and is worked in full in sample-experiment.eco.

ModelArgumentsClassic result
logisticr K N0 stepsVerhulst growth toward K.
islandc e pool S0 stepsMacArthur–Wilson equilibrium richness & turnover.
competition(two-species Lotka–Volterra)Coexistence or exclusion.
hardyweinbergAA Aa aaAllele frequencies + χ² against equilibrium.
eulerlotkalx:mx pairs, per ageNet reproductive rate R₀ and intrinsic rate r.
markrecaptureM C RLincoln–Petersen population estimate.
model: logistic 0.15 120 5 60         # r, K, N0, steps
model: island 0.4 0.1 100 0 40         # c, e, pool, S0, steps
model: hardyweinberg 298 489 213      # a genotype census
model: eulerlotka 1.0:0 0.8:1.5 0.5:2.0 0.2:1.0
model: markrecapture 120 90 30         # marked, caught, recaptured
your observations

data — bring your own field counts

Your entered datasets are narrated by the same instruments as the simulated phases, and compared pairwise. Two entry styles — pick whichever your clipboard has.

FormMeaning
data: <label> name=count …Named counts — a species survey, a genotype tally, an activity budget.
data: <label> word word word …Bare tokens tally themselves, like clipboard tick-marks — ideal for scoring an ethogram live.
data: pondA cattail=18 duckweed=44 frogbit=3 azolla=9 rush=6
data: pondB duckweed=51 azolla=2 lily=12 rush=6
data: coop  peck peck peck flap strut peck dustbathe flap
field notebook

note — qualitative observations

Notes travel with the run and appear in the report. Pin one to a phase or dataset by naming it in parentheses.

note: sampled both ponds after two dry weeks
note(bloom): five keys took nearly all the traffic, as designed
note(coop): tallied one hen for ten minutes before feeding
phylogeny

tree — a phylogeny in Newick

Standard Newick, the same format every phylogenetics course and paper uses. The runner draws the cladogram and counts its clades.

tree: pondlife (Porifera,(Cnidaria,((Mollusca,Annelida),(Arthropoda,(Echinodermata,Chordata)))));
genetics

cross — a genetic cross

Parent genotypes as one letter-pair per gene (up to three genes). Add observed counts to get a χ² against the expected ratio, or incomplete for incomplete dominance.

FormMeaning
cross: P1 x P2Predict the ratio (e.g. Rr x Rr, or dihybrid RrYy x RrYy).
… observed n1 n2 …Add your F2 counts, in ratio order → χ² goodness-of-fit.
… incompleteHeterozygote shows its own phenotype (1:2:1, not 3:1).
cross: Rr x Rr observed 5474 1850    # Mendel's seed shape (his 1866 counts)
cross: Bb x Bb incomplete            # blue Andalusian: 1:2:1
cross: RrPp x RrPp                   # two-gene comb interaction
the hypothesis

expect — commit before you run

The point of the protocol: state your prediction in advance and let the engine grade it. A scope in parentheses is a phase label or a data label. Two flavours:

FlavourForm
Quantitativeexpect: metric(scope) > < >= <= = value
Pairwiseexpect: brayCurtis(a, b) > value  ·  jaccard(a, b) <= value
Qualitativeexpect: metric(scope) is band

Metrics include evenness, shannon, hill1, richness, dispersion, and the pairwise brayCurtis / jaccard / sorensen. Qualitative bands are the exact words the report uses: even / uneven, random / regular / clumped, and survivorship is type1|type2|type3.

expect: evenness(graze) > 0.9
expect: hill1(bloom) < 20
expect: brayCurtis(graze, bloom) > 0.5
expect: evenness(bloom) > 0.9        # deliberately wrong → REFUTED
expect: evenness(bloom) is uneven      # qualitative, same bands as the report
expect: survivorship is type3

How grading works

Each expect is checked against the run and stamped. The bands a qualitative claim grades against are the same thresholds the narrated report prints — one source of truth, so a reading and a verdict can never disagree.

✅ CONFIRMED
The run matched your prediction.
❌ REFUTED
The run contradicted it — a real result, not a failure.
⚠ UNGRADEABLE
The claim can't be judged honestly (e.g. a survivorship claim with no census, or a phase compared to a dataset). Flagged, never guessed.

How to run it

# the bundled worked example (with one deliberately-wrong hypothesis)
./gradlew ecologyExperiment

# your own protocol
./gradlew ecologyExperiment -Pspec=path/to/your.eco
No build? You never have to touch Gradle to write a protocol. Type your data into the Interactive Lab's Workbench, and its transfer box hands you the .eco lines to save — then run them whenever you have the repo, or just keep iterating in the browser. The Lab Manual ends each lab with a ready-to-copy protocol.
