All four strategies receive the same operations. The teal card has the lowest height. This is the project's thesis made visible — no single tree wins every workload, which is why CSRBT morphs between them. Try Insert 1‥20 ascending: AVL and WB stay short, Red-Black stays within 2×optimal, and Splay collapses to a spine (the exact degenerate case the audit flagged, where the engine's recursive health-gate validators would overflow the stack at large n).

Faithful to the engine. The balancing here is reimplemented from csrbt-core/strategy: Red-Black (CLRS insert/delete fixup), AVL (height rebalance), WeightBalancedStrategy BB[Δ,Γ] with the shipped Δ=3, Γ=2, and Splay (splay-on-access). Every node carries an intrinsic subtree size, maintained through rotations, which powers the O(log n) select/rank/median — CSRBT's headline feature. The JS core was fuzz-tested (4000 mixed ops/strategy) against a sorted-set oracle with full invariant and order-statistic checks before shipping.
