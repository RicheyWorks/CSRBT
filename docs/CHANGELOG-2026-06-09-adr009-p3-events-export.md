# CHANGELOG 2026-06-09 — ADR-009 P3: structured events + the visualizer contract

"Self-adapting" was a log line; now it is consumable. Two additive pieces, no behavior
change, closing the last implementation item the external review's gap list got right.

## `core.event` (new) — the listener seam

- **`TreeEvent<K>`** — a sealed interface of records, all in one file: `Insert` / `Remove` /
  `Evict` / `Morph(from, to, committed)` / `Repair(healthy)` on the set, and `Quarantine` /
  `Heal` / `Retire` / `Promote(from, to, failover)` / `ShadowRebuild` / `MemoryCeiling` on
  the ensemble. JSON logging, Micrometer counters, or a visualizer feed are one exhaustive
  switch away — that layering is deliberately the caller's, not the library's.
- **`TreeEventListener<K>`** + `setEventListener(...)` on `OrderedSet` and
  `EnsembleOrderedSet` (null unregisters). Listeners run synchronously on the mutating
  thread under the set's locks, exactly like the log lines they mirror — the contract
  (fast, non-throwing, non-reentrant) is documented loudly.
- **Events fire on *effective* changes only** — duplicate adds, absent removes, and
  same-strategy morph requests emit nothing; a failed health gate emits
  `Morph(committed=false)`, the no-data-loss path made visible. Controller-driven repairs
  flow through the ensemble's lifecycle methods, so `checkHealth()` emits its
  quarantines/heals/failovers with zero controller changes.
- **Allocation-free when unobserved:** every emit site is `if (events != null)`; with no
  listener the write path allocates nothing for the seam. Benchmark row (sandbox):
  150k inserts, no listener **55.8 ms** vs counting listener **63.4 ms** — the unobserved
  path pays nothing, and the observed path pays only the records.
- **Deliberately absent:** rotation events. The engine keeps no rotation counter, and
  instrumenting `MutableTree.rotateLeft/rotateRight` is hot-path surgery deferred until a
  consumer demands per-rotation granularity (noted in the `TreeEvent` javadoc).

## `core.export.TreeExport` (new) — the visualizer contract

- `toJson(OrderedSet<K>)` — dependency-free JSON: strategy, size, height, write meters, and
  the node tree (key / color / subtree size / depth / left / right). Keys render via
  `String.valueOf` + escaping, so any key type exports. Reads live structure outside the R1
  guard, documented as a diagnostics/export seam like `getTree()`.
- The reference output is checked in at **`docs/visualizer-contract.json`** (generated by
  the real exporter over a 7-key RB tree) — a p5.js/JavaFX drawer builds against that file,
  not against this library.

## Tests (`TreeEventExportTest`, 7 tests; suite 473, green)

- Effective-changes-only semantics (duplicates/absences/no-op morphs silent; evict on
  window overflow; null unregisters); morph from/to + verdict; repair verdict.
- Ensemble lifecycle: controller `checkHealth()` emits quarantine + heal; explicit promote
  emits `failover=false`; a dissenting VERIFIED primary emits the failover promote + its
  own quarantine; ceiling breach/recovery and Option C cadence rebuilds emit.
- The benchmark row above, plus exact-count verification that every effective insert was
  observed.
- Export: schema fields, balanced braces, RB-root-is-black, quote escaping, empty-set form
  (`"root": null`, `"height": 0`).

With P1/P2/G0 already landed, this closes every implementation item in ADR-009; G1
(Gradle/JMH) and G2 (jqwik) remain held on their documented triggers.
