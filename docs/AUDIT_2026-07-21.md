# CSRBT — Independent Architecture & Correctness Audit

**Repo:** RicheyWorks/CSRBT · audited at `3fc8507` (post-`v0.1.0`)
**Date:** 2026-07-21
**Scope:** Full sweep of `csrbt-core` — the four balancing strategies and morph health gate, order-statistics augmentation, the ensemble/persistence/engine-family concurrency layer, and the control-plane / evolution machinery. Findings verified against source with file:line references.

---

## 1. Executive summary

CSRBT is an unusually ambitious and, on its live paths, unusually *honest* piece of work. It is a pluggable ordered-set engine: one generic `OrderedSet<K>` API backed by interchangeable Red-Black, AVL, Splay, and parameterized Weight-Balanced strategies, able to morph between them at runtime behind a health gate, with O(log n) order statistics over a subtree-size augmentation, a multi-tree ensemble for O(1) adaptation and failover, a path-copying persistent engine, a B+tree, and an evolution machine that searches strategy parameters and — to its credit — reports a *falsifiable negative result* when the search fails to beat the fixed strategies.

Three independent audit passes (core correctness, concurrency/ensemble, evolution/quality) converge on the same picture: **the core balancing algorithms are correct and genuinely well-tested; the concurrency primitives that are claimed to be sound mostly are; and the project is refreshingly candid about its own limits.** The real defects cluster in three places:

1. **Recursive validators on a data structure that can be O(n) tall** — a latent `StackOverflowError` on the morph/self-repair path at scale, which the test suite never triggers because every morph test caps at n≈1000 (F-C1). The engine's *read* paths were deliberately made iterative for exactly this reason; the *health gate* was not.
2. **A crash-unsafe persistence layer** — snapshots are written in place with truncation, no temp-file + atomic rename, no fsync, and IOExceptions are swallowed, so a crash mid-write destroys the previous good snapshot (F-P1).
3. **One overstated claim in the evolution machine** — the fitness function's write-cost term is identically zero on the path that actually runs, which partially manufactures the very negative result being celebrated (F-E1).

None of these is a correctness bug in the everyday insert/delete/search path. The headline data structure works; the sharp edges are at the margins (degenerate scale, crash durability) and in one honesty footnote.

## 2. What's genuinely well-built (verified, not filler)

- **Balancing correctness across all four strategies.** RB insert- and delete-fixup (all four double-black cases, NIL-sentinel parent threading), AVL/WB/Hybrid `rebalanceUp` (single + LR/RL double rotations, correct post-rotation continuation), and the split-and-join splay delete were traced by hand. Parent relinking, root detection via the NIL sentinel, and subtree handoff are correct; **no dropped subtree or mis-relinked parent found.** The notorious two-children-delete splice cycle is correctly handled with local relinking plus an explicit parent fix.
- **Order-statistics augmentation is sound.** `TreeNode1.size` is intrinsic and separate from the pluggable augment slot, maintained on every structural link and recomputed locally (not to the root) by the O(1) rotation variants — dropping insert from O(height²) to O(height). `select`/`rank`/`rankCeiling`/`countInRange` are fully iterative with no off-by-one this audit could construct. *(This audit's companion visualizer independently re-derived all four strategies and fuzz-tested them — 4000 mixed ops each — against a sorted-set oracle with select/rank/median checks: all pass, and the size field stays exact through every rotation.)*
- **The test suite exercises invariants after rebalancing, not just API smoke.** `StrategyInvariantTest` drives randomized mixed ops against a `TreeSet` oracle with periodic structural validation, asserting per-strategy RB validity (root-black, no red-red, equal black-height), AVL |bf|≤1, BST order, and order-statistic exactness — plus degenerate, delete-heavy, duplicate, and drain-to-empty cases.
- **The READ_REPLICA epoch protocol is a correct left-right/Dekker construction** (flip → drain → mutate vs enter-read → re-check → read). A reader racing the flip fails the `p == primary` re-check and retries without dereferencing the mutating tree. Genuinely sound lock-free reads.
- **Optimistic quorum votes are provably consistent** under the single-writer model (unanimity ⇒ the answer is invariant to pre/post-write placement ⇒ a valid consistent cut), and **failover is a real O(1) volatile primary swap**.
- **The path-copying persistent engine** (immutable final-field nodes, single-store volatile-root publication, iterative path-copy, Adams BB[α] balance, count-funded order stats) delivers genuinely wait-free readers and true O(1) in-memory snapshots.
- **The B+tree** split/merge/borrow/underflow and its `validateStructure` gate were reviewed with no correctness defect; concurrency is coarse `synchronized` but honestly documented.
- **The evolution experiment is real science.** Every RNG is explicitly seeded, shadow sampling is modular (not random), fitness is pure, and the verdict metric is **comparisons counted at the comparator seam**, not wall-clock — so the negative result reproduces byte-identically. Reporting "our search did not beat the fixed strategies" as the finding, with receipts, is rare and commendable.

## 3. Verified defects (prioritized)

### P0 / P1

**F-C1 (Medium-High). Recursive invariant validators overflow the stack on a degenerate tree — the morph & self-repair paths can crash at scale.**
`util/StrategyHealthCheck.java` validates candidates with `isBst` (107-112), `blackHeight` (121-128), `balancedHeight` (135-143), all **recursive on tree height**, and clause 3 runs `isBst` for *every* strategy. `OrderedSet.setStrategy` (524-527) builds the candidate by inserting the in-order (ascending) key list; for `SplayStrategy` this yields a left spine of height n. Validating it recurses to depth n → `StackOverflowError` (an `Error`, not caught by the gate's `RuntimeException` guard) escaping `setStrategy`/`selfRepair`. **The codebase already knows about this hazard** — `EnsembleBenchmarkTest` comments call it out and the read/export paths were deliberately made iterative (a 50k-key spine is exported fine) — but the health gate and `TreeNode1.deepCopy`/`blackHeight`/`toIndentedString` were not. Morph tests cap at n≈1000, staying under the limit, so the suite never triggers it. *Fix: make the validators and clone iterative (explicit stack), matching the read paths.*

**F-P1 (High). Persistence is non-atomic and non-durable; a crash mid-save destroys the prior snapshot silently.**
`FilePersistenceAdapter` (all three `saveSnapshot` paths: 67-91, 318-340, 450-475) writes directly to the live path via `Files.newBufferedWriter` (default `TRUNCATE_EXISTING`) — **no temp file, no `ATOMIC_MOVE`, no `force()`/fsync** — and swallows `IOException` (logs, returns from the `void` method). A crash/disk-full/power-loss between the header and data writes leaves the file truncated; because the target was truncated in place, the previous good snapshot is already gone. On reload, a coincidentally-order-valid prefix loads a **silently short set**; otherwise the snapshot is lost. The caller gets no exception and believes the save succeeded. *(A post-load structural gate catches torn files only when the truncation produces an invalid structure.)* *Fix: write to `.tmp`, flush + `force(true)`, `Files.move(ATOMIC_MOVE)`, propagate the IOException.*

**F-E1 (Medium-High). The evolution fitness function's write-cost term is identically zero on the path that runs — partly manufacturing the negative result.**
`Fitness.java:85` computes `writeCost = writeFraction × rotationsPerWrite`, and its Javadoc claims this term is "fully realized." But both evolution controllers feed the monitor through the 1-arg `recordAdd/recordRemove` overloads (`PolicyEvolutionController.java:139/145`, `PolicySearchController.java:107/113`), which pass `rotations=0`. So `rotationsPerWrite` stays 0 and **writeCost = 0 for every candidate and the incumbent, always.** Fitness collapses to read cost alone; on write-heavy families (delete-heavy, sequential) cost ≈ 0 for all candidates and selection is near-arbitrary; and the rotation axis — the entire point of the Δ parameter — is invisible to selection. The negative result ("searched parameters don't beat the fixed four") is therefore narrower than stated, and the Javadoc's "fully realized write term" is factually false on the live path. *Fix: supply real per-op rotation counts, or footnote the result honestly.*

### P2 (Medium)

- **F-C2. The health gate selects its structural check by class *simple-name string*** (`StrategyHealthCheck.java:62-79`); any strategy whose name isn't one of four literals (`"RedBlackStrategy"`, `"AVLStrategy"/"HybridStrategy"`, `"SplayStrategy"`) falls to `default → validateInvariant()` which defaults to empty. A subclassed/renamed RB strategy would have its red-black invariant **never checked** — the gate could publish a black-height-broken tree that still passes the contents/size/BST clauses. The gate is "total" only for exactly those four names.
- **F-N1. Ensemble persistence availability is non-deterministic across lifecycle** (`FilePersistenceAdapter.java:566-577`): `saveSnapshot` only handles an `OrderedSet` or `PersistentRankedSet` *primary*; after a failover/promotion makes a `BPlusTreeEngine` member primary, the identical call throws at runtime. B+tree has no snapshot path despite being a first-class member.
- **F-Q1. `TreeGenome` (1924 lines) is superseded ceremony.** Seven nested trait classes, ~254 members, still carrying `static Random`, `UUID.randomUUID()`, and `System.currentTimeMillis()` nondeterminism. The real working genome is `PolicyGenome` (242 clean lines), which disavows it. Individual methods are `@Deprecated` but the class isn't; it's dead-by-default (the control-plane flag defaults on). With the duplicated nested `MorphPolicy` and legacy decision surface in `GenomeDrivenTreeController` and the nondeterministic `StrategyBattleRunner`, this is ~2,600 lines of superseded/duplicated/nondeterministic code shipped in `main`.

### P3 (Low)

- **F-C3.** The gate validates `HybridStrategy` with strict AVL (|bf|≤1) but Hybrid's own invariant allows |bf|=2 below its depth threshold — a legitimately-balanced parameterized Hybrid is flagged unhealthy, forcing needless rebuilds. (Shipped default Hybrid is strict, so latent.)
- **F-C4.** `OrderedSet.selfRepair` (581-595) publishes the rebuilt tree *before* validating it, unlike `setStrategy` which validates first — the "incumbent untouched on failure" guarantee doesn't hold on the repair path.
- **F-P2.** `optimisticVotesOverride` is a non-volatile field read on the concurrent vote hot-path (`EnsembleOrderedSet.java:77/314/1031`); under unsafe publication a reader can observe `null` and fall back to the process-global static, defeating the per-instance isolation it's meant to guarantee. Make it `final`/`volatile`.
- **F-P3.** `TreeHistory.checkpoints` (named deep-copied trees) has no eviction (only undo/redo/audit are capped) — unbounded heap growth for a long-running process that checkpoints periodically.
- **F-Q2. UCB1 reward is not normalized** (`PolicyBandit.java:112`, `c=1`): with rewards ~0.1–1.5 but inter-arm gaps ~0.001–0.01, the exploration bonus swamps the signal and selection is effectively round-robin within any realistic budget. (Not on the headline experiment path, which uses the (μ+λ) controller.)
- **F-Q3.** The cost-model scorer can recommend a morph to Splay on a hot-key *read* workload where "reads never splay" (its own comment) — an O(n) rebuild that can't help the read path. Morph *cost* is measured (`buildNanos`) but never fed back into the decision (the amortization gate is accepted-and-ignored).

## 4. Claim-honesty ledger

The README makes strong claims; most hold, a few are oversold. Verified:

| Claim | Verdict |
|---|---|
| Four correct, health-gated strategies + morphing | **Real** (F-C1/F-C2 are edge/scale caveats, not everyday bugs) |
| O(log n) order statistics via subtree-size augment | **Real** and exact through rebalancing |
| Wait-free readers | **Partly / oversold** — true only for the persistent engine; strategy-backed reads use a blocking StampedLock, B+tree reads are `synchronized`. The README body concedes this, contradicting the headline. |
| O(1) snapshots, path-copying persistent engine | **Real** (in-memory) |
| Quorum-verified reads, lock-free unanimous votes | **Real, with documented weakenings** (non-voted strides serve unverified; a shrunk quorum can degrade to a single member reported as "unanimous") |
| Instant failover | **Real** |
| Memory ceilings | **Aspirational** — observed/logged, never enforced (the `maxMembers` build cap *is* enforced) |
| "Searched parameters don't beat the fixed four" | **Supported and reproducible** — but narrower than a naive reading (WB-only search, on a fitness whose write half is dead-zero, F-E1). The README's ADR-012 disclosures reinforce this transparently. |

The overall posture — reporting a negative result with a deterministic metric, disavowing superseded code in its own docs, conceding the evolved winner is just the literature default — is markedly more honest than typical. The one place the code oversells what it measures is F-E1's Fitness Javadoc.

---

## 5. Recommended priorities

1. **F-C1** — make the health-gate validators + `deepCopy` iterative (match the read paths); add a large-n degenerate morph test so the suite catches regressions.
2. **F-P1** — atomic + durable snapshot writes (temp → fsync → atomic rename), propagate IOExceptions.
3. **F-E1** — supply real rotation counts to the evolution fitness, or footnote the negative result precisely.
4. **F-C2 / F-N1** — validate by strategy capability not class-name string; give the B+tree a snapshot path (or gate promotion on persistability).
5. **F-Q1** — retire `TreeGenome` / legacy `GenomeDrivenTreeController` / `StrategyBattleRunner` (~2,600 lines) now that `PolicyGenome` + the control plane are the live machine.

**Companion:** an interactive `docs/tree-visualizer.html` (delivered alongside this audit) reimplements all four strategies live — insert/delete/search with animated rotations, subtree-size order statistics, strategy morphing, and a compare-all-four mode that makes the "no single tree wins every workload" thesis visible (and demonstrates F-C1's degenerate splay spine directly). Unlike the existing replay-only `demo/visualizer.html`, it runs the algorithms in the browser; its JS core was fuzz-tested against a sorted-set oracle before shipping.
