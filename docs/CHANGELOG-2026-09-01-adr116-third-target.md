# Changelog — 2026-09-01 — ADR-116: the third target

The science engine is behind the contract. A robot can lint, run and grade an
`.eco` protocol, run the strategy arena, read the adaptive controller's morph
log, run the field day and export the bundle — through the same gateway and
both transports, with nothing in them changed. And the canonical oracle it
brought found the shipped session stale.

## New — `csrbt-experimental`

`LabConsole.java` (verbs `lint`, `run`, `export`, `battle`, `adapt`,
`fieldday`, `observe`; a protocol crosses as one base64 token; `dwc:` refused
before parsing); `:csrbt-experimental:harnessClasspath`; `LabConsoleTest`
(5). 256 tests green, javadoc clean.

## New — `tools/harness_plugin_lab.py` (`csrbt-lab`, 8 actions)

2 READ (`protocols`, `lint`), 5 NAVIGATE (`run-protocol`, `run`, `battle`,
`adapt`, `field-day`), 1 MUTATE (`export`, into plugin-owned scratch). Bounds
and a runnable protocol example in the schema. `--target lab` / `--target all`
on both transports via `harness_targets`.

## Fixed — the shipped session was behind the engine

`docs/ecology-experiment-session.json` and `docs/experiment-out/session.json`
lacked `entered[*].quantity` (the DwC quantity type from ADR-107/108).
Regenerated by the canonical task; text exports were already identical;
Office files left as shipped (structure-pinned). `verify_engine_sessions` now
uses the written classpath before hunting `~/.gradle` and reports **26/26** —
its standing `NOT VERIFIED` since ADR-108 is closed.

## New — `tools/verify/verify_lab.py` (**35 checks**) and `tools/mutate_lab.py` (**9 killed, 0 survived, 1 equivalent**)

## Fixed — the mutant runners

A suite that crashed under mutation printed no `FAIL` line and was reported
`SURVIVED`. `mutate_lab`, `mutate_organism` and `mutate_mcp` now report it as
`BAD MUTANT: the suite crashed rather than failed`.
