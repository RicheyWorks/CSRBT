The Experiment Guider
← the living-systems lab

How to run an experiment in this ecosystem — for scientists and engineers. The same discipline runs a meadow study and a storage-engine benchmark: write the rule before the run, pin the seed, pay warm-up off the clock, and let the verdict say no. This page teaches the method, then builds your experiment with you — a ready-to-run .eco protocol, or a pre-registered measurement plan. Everything works offline and prints clean.

The five commitments

None of these are theory. Every one was learned here the hard way, and each story below carries its receipt — the document where the number lives.

1 · Write the rule before the run

Decide what result would change your mind — and write it down — before you see any data. A bar set after the numbers arrive is a bar the numbers set. In this ecosystem the habit is built in: the .eco runner grades hypotheses that were in the spec before it ran, and every performance experiment states its decision rule in the test's javadoc before the first timed pass.

Three pre-registered verdicts, one day. The cold-scan experiment set its bar at 5× the raw-read floor and measured 524× — the trigger FIRED and a held feature earned its build. The preserve-cadence experiment set a 25%-of-churn viability bar and measured 191% — the popular workaround was PRICED DEAD, and nobody gets told "just preserve more often" again. The memory-bound experiment set a 1 KB-per-key bar and measured 181 B — the disk-pages seam STAYS HELD. Two of the three said no. All three verdicts were kept.
sources: EXPERIMENT-2026-08-20-cold-triggers.md · EXPERIMENT-2026-08-20-memory-bound.md

2 · Pin the seed

A result nobody can reproduce is an anecdote. Every workload generator here takes a seed, and the protocol runner is deterministic to the byte: same spec, same bytes. Reviewers do not have to trust your run — they can have it.

The experiments above are not tables in a document that someone once produced — they are checked in as seeded tests (ColdScanExperimentTest, PreserveCadenceExperimentTest, MemoryBoundExperimentTest), so any machine can re-run the verdict of record.
source: EXPERIMENT-2026-08-20-cold-triggers.md ("checked in so any machine can reproduce them")

3 · Pay warm-up off the clock

On a JIT-compiled runtime, the first pass through any code path pays compilation on your stopwatch. Run one full untimed pass first; only then start timing.

Before ADR-022, the strategy tournament timed a single cold pass — and whichever competitor ran first paid the JIT bill: 62.4 ms cold vs 17.2 ms warm (3.6×) for identical work. Rank orders differed across identical inputs. The fix: one untimed warm-up pass, then timed passes on fresh contexts.
source: ADR-022, finding V-D

4 · Take the median of three

One timed pass is one sample of a noisy machine. Three timed passes on fresh state, keep the median — it absorbs a single spike without averaging it into your result. Report the phase decomposition too: a total that cannot say where the time went cannot name the enemy.

The cold-scan verdict was usable because it decomposed: inflate 29 ms, recover 61 ms, scan 434 ms of a 524 ms route at n=60,000. The decomposition named the enemy (the scan through a store recovered only to be read once) — and the fix it pointed at measured 33× faster.
source: EXPERIMENT-2026-08-20-cold-triggers.md

5 · Measure the realized thing

The easiest number to collect is usually a proxy for the number you care about. Ask of every metric: is this the behavior, or the worst case of the behavior? Is the subject actually allowed to do the thing I claim to be measuring?

The tournament once benchmarked the Splay strategy with splaying disabled — searches ran through a read path documented "never splays," so the self-adjusting structure could never self-adjust in the very workloads written to favor it. And the "search depth" metric was the root height (worst case, weighted ×3 in the score), not nodes actually touched: it read ~3000 where the realized depth was under 100. Splay finished dead last in every seed — a structurally guaranteed verdict, not a measured one.
source: ADR-022, finding V-C

Two habits that keep verdicts honest

Compare against a floor

Before comparing solution A to solution B, name the floor — the least any solution could possibly do. The cold-scan experiment measured its route against the cost of reading the archive's bytes once; "524× the floor" is a claim about the problem, where "5× faster than the other guy" is only a claim about the other guy.

A refuted result is a result

The report keeps what the run refuted, in writing, next to what it confirmed. The .eco runner prints REFUTED beside a failed hypothesis instead of hiding it, and audit documents here record dismissed suspicions alongside confirmed findings — a suspicion examined and cleared is knowledge, and it stops the next person from re-hunting it.

This is also why UNGRADEABLE exists as a third verdict: a hypothesis naming a phase that doesn't exist is a spec bug, not a result — the runner refuses to guess. See the .eco reference.

Design your experiment

Pick a track. Both walks end with something you can run: a .eco protocol file, or a pre-registered measurement plan with a test skeleton. Your entries autosave on this device.

Already have a protocol? Import a .eco

Paste a protocol below, choose a file, or drop one on this card. Importing replaces the Designer's entries and runs the pre-flight lint over what came in. Directives the Designer doesn't edit (cross:, tree:) are kept in the extra-lines box; comments are dropped, the way the parser drops them.

Step 1 — name the study

Keys are species · touches are abundance · time is counted in operations. The seed makes the whole run reproducible — same spec, same bytes.

Step 2 — write the story as phases

Each phase is a named stretch of operations with one access pattern. uniform spreads traffic evenly; hot concentrates it on a few keys (a bloom, a disturbance); churn adds and removes keys (turnover, seasons).

No phases yet — a study needs at least one.

Step 3 — set the abiotic stage (optional)

Factors scale the theory models' rates and capacities: area scales K and extinction pressure, wind scales colonization, temperature multiplies rates, distance decays immigration. Leave a factor at its neutral value to leave it alone — 1.0 for the first three, 0 for distance (no isolation).

Step 4 — run theory beside the field (optional)

Models run next to the simulation so prediction and observation share a report. Parameters are space-separated, in the order shown.

No models yet.

Step 5 — enter field data (optional)

Your own observations, graded by the same instruments as the simulation. Write species=count pairs, or bare names that tally like clipboard marks (peck peck flap counts two pecks and a flap).

No datasets yet.

Step 6 — pre-register your hypotheses

This is the step that makes it an experiment. Each expectation is graded CONFIRMED or REFUTED after the run — and you are writing it now, before the run. Numeric: metric(phase) < value. Qualitative: metric(phase) is word, graded against fixed bands.

No hypotheses yet — without one, it's a demo, not an experiment.

Comparing a simulated phase to an entered dataset grades UNGRADEABLE on purpose — the numbers share no species. Compare phase-to-phase or dataset-to-dataset. Advanced directives (cross: Mendelian genetics, tree: Newick phylogenies) are in the full .eco reference; paste them into the extra-lines box below.

How a verdict is earned

    
Every hypothesis gets exactly one of three verdicts. There is no "sort of."

    
CONFIRMED — the observed value satisfied the test you pre-registered.

       REFUTED — it didn't. This stays in the report; a refuted prediction is a
       measurement of your model, not an embarrassment.

       UNGRADEABLE — the hypothesis could not be tested: it names a phase or
       dataset that doesn't exist, or compares a simulated phase to entered field data (they share no species,
       so the number would be noise wearing a decimal point). An untestable hypothesis is a spec bug, and the
       runner says so instead of guessing.

Qualitative hypotheses — metric(args) is word

    
Graded against the same fixed bands the narrated report uses, so your words and the
      report's words can't drift apart.

    

      
formallowed words

      
evenness(p) is …very-even moderate uneven dominated

      
turnover(p, q) is …low moderate major (Bray–Curtis bands)

      
overlap(p, q) is …high partial little (Pianka bands)

      
fit(p) is …geometric brokenstick uniform (rank-abundance best fit)

      
survivorship is …type1 type2 type3 (no parentheses — reads the run's census)

    

    
Everything beyond this deliberately stays out of the format — a hypothesis that needs more
      belongs in Java against the instruments directly. The format stays small on purpose.
      Full grammar: the .eco reference.

  


  

    
Engineering verdicts

    
Performance experiments here grade a held decision, not a number in isolation. The
      pre-registered rule names the bar; the run answers one of:

    
THE TRIGGER FIRES — the measured cost cleared the bar; the held feature
      earns its build, with its number attached (the cold-scan trigger fired at
      524× against a 5× bar).

      STAYS HELD — the bar wasn't met; the seam waits, and the price you
      measured is recorded so the next reviewer doesn't re-litigate it from intuition
      (the disk-pages seam stays held at 181 B/key against a 1 KB bar).

      PRICED DEAD — a workaround everyone would reach for was measured
      unviable, in writing (preserve-often died at 191% of churn time against a 25% bar).

    
Sources for all three numbers:
      cold-triggers and
      memory-bound.
      Notice the pattern: verdict, bar, and consequence live in one sentence. Write yours the same way.

The wider organism

    
The storage ecosystem around the index has its own instruments, built for exactly this method —
      every one is a seam an experiment can hold onto:

    

      
engineinstrument

      
Rub
          the observer: Vitals meters and pulse() — op-relative deltas between
              two readings, no wall clock involved

      
Sizzle
          deterministic chaos: seeded fault and latency injection, so a failure experiment reproduces
              like any other run

      
Twine
          stats() — a nonzero journalReplays is the observable trace of an
              absorbed crash

      
WholeHog
          the composed organism: Organism.report() reads every meter in one call
              (and two consecutive physicals are pinned identical — a physical never changes the patient)

    

    
The pattern worth stealing: instrument first, then experiment. Every engine above grew a
      meter before any claim was made about it — you cannot pre-register a rule about a number you
      cannot read.
